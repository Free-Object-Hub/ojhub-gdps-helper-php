# ojhub-gdps-helper-php
Так называемый "Legacy PHP" бекенд Object Hub, до недавнего времени являлся эталоном протокола, но теперь застыл на версии V133R0  
  
# Зависимости  
1. https://github.com/WhichBrowser/Parser-PHP  
Вам нужно вручную склонировать репозиторий в папку `uaparser/`  
2. MaxMind GeoLite2, ложите mmdb файл в папку `country/` (Именно с городами!)  
  
# Стек  
- PHP 8.4 (на 8.5 не тестировалось, и наверное не будет, но если заработает - клёво)  
- MariaDB/MySQL (исторически Object Hub успел поработать на MySQL 5.7, но сейчас живёт на MariaDB 11.8)  
- Никакого Redis (потому что Legacy PHP писался под вялые shared хостинги где даже memcached считается технологией 22 века и его нет)  

# Вы хотите поднять этого монстра?  
1. Откопайте схему БД из [ojhub-node](https://github.com/Free-Object-Hub/ojhub-node) репозитория (она застряла на V133R0) и импортируйте её в базу данных  
2. Напишите ваши учётные данные от базы данных в `server/133/api/secretCfg.php`  
3. Так как весь legacy php построен на path-based роутинге, убедитесь что в nginx/apache/где\_вы\_там\_гоняете\_fastcgi у вас указаны верные пути и запрос на `/server/133/loginT.php` отдаёт ответ  
4. Вы подняли GDPS Helper 2.1!  
  
# Форк  
Если вы сравните [GDPS Helper](https://github.com/GDPS-Helper/helper1901source) репозиторий, и этот Legacy PHP, то вас встретят вот такие забавные вещи:  
- Почти идентичная структура классов  
- Почти идентичные функции рендера  
- Отсутствие git  
- Очень кривой и странный код  
- Одинаковая ненависть к PHP и бекенду в частности  
  
# Развитие?  
Пусть Legacy PHP целиком удалён из продакшна ещё в августе-сентябре 2026, но планы на его "воскрешение" и "допинывание" у меня все ещё есть!  
В Legacy PHP должны быть костыли для частичной поддержки протокола V133R1 (см. в конце `server/133/api/api.php`), и honestly держать Legacy PHP рабочим намного приятнее чем nodejs, так что... я ничего не обещаю, но если когда нибудь на меня хлынет волна ностальгии, я доведу Legacy PHP до протокола V133R3  
  
# Какие сейчас расхождения есть  
- openGo использует ALTCHA, Legacy PHP застыл на reCaptcha  
- likesT.php отсутствует целиком  
- Нет в наличии - Портфолио, Загрузчик версий  
- Вакансии целиком являются одной огромной уязвимостью  
- Новости рендерятся как объект (а не как массив)
